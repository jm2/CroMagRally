Reviewed commit: `72eb0b1d46b4c93340a3d43744b9ae401a1e0f63`.
This assessment supplements the historical June review in `REVIEW.md` and the
completed September backlog. It describes remaining defects in the current
tree, rather than reopening already-fixed findings.

The recent work has materially improved startup validation, network lifecycle
handling, persistence, and release checks. The sanitizer build and all exercised
regressions pass. Nine remaining defects were identified and filed as GitHub
issues, with matching unchecked entries in [task.md](task.md). No production
code was changed during this review.

The most consequential remaining gaps are race completion outside the network
simulation clock and incomplete validation in older binary asset loaders. The
other findings affect AI guidance, split-screen audio, saved score metadata,
optional Debian packaging, and a latent model-group parser bug. There is no
evidence from these checks of a universal startup failure or a failure in the
previously repaired save/migration paths.

P2 denotes an actionable correctness or robustness defect; P3 denotes a lower
priority latent defect. These are review priorities, not exploitability scores.
The issue bodies contain pinned source links, scope, correction criteria, and
focused validation expectations.

For #26, a client hold render decrements cooldown using the last host timestep
even though no simulation advanced. A catch-up render can apply several
timesteps but decrement only once. The same outer-loop decrement also ignores
the paused/advancing distinction in `StepGameSimulation`. Completion therefore
needs a shared simulation or host-authoritative policy. This finding was traced
in the source; an actual multi-process race finish was not reproduced.

For #27 and #28, the trust boundary is installed game data. A compressed-input
length limit does not establish a decoded-output limit, and a successful model
header read does not validate the subsequent arrays or texture buffer. These
findings warrant controlled rejection before use. No remote delivery path or
working exploit is claimed, and no crashing payloads were generated for them.
Passing the current malformed-resource suite does not cover these different
loader paths.

The isolated gameplay checks compiled the actual production functions with
sanitizer instrumentation and normal inputs, excluding unrelated UI sections.
Allocation/terrain helpers were isolated, and scoreboard persistence was stubbed
so user saves were untouched. A two-point straight path produced first direction
`(1,0)` and terminal direction `(0,0)`; querying its first point returned
`found=1, direction=(-nan,-nan)`. A valid Easy-session race with a Hard local
preference saved difficulty `3` instead of `1`. The audio check retained the
production vector math: two opposing listeners yielded the same channel volumes
as one listener, and a source next to player three was silent when the first
two players were distant. These checks establish the function-level defects,
not their frequency during live play.

The review covered first-party startup and CLI handling; gameplay, AI, weapons,
checkpoints, timing, and input; network transport, message validation, readiness,
departures, and pause flow; asset loaders, terrain, rendering/object lifetimes,
skeletons, and audio; preferences, scores, Android asset extraction, and tvOS

this was not an exhaustive line-by-line audit of SDL, Pomme, gl4es, or stb_image.

The build used SDL's offscreen backend because the local environment lacked
desktop Xcursor development headers. Rendering used software GL and dummy audio,
so these results do not validate physical displays, audible output, or hardware
drivers. Offscreen smoke tests disable leak detection for known process-lifetime
Mesa allocations; address/undefined-behavior failures remain fatal. Unit tests
retain their normal sanitizer checks. Scratch builds, fixtures, and isolated
preferences were removed after the review.

Windows, macOS, Android, iOS, and tvOS configuration and source paths were reviewed
but not built or run on native devices in this session. Likewise, the review did
not publish a release, perform clean-system DEB/RPM installs, play every battle
mode to completion, or run a full multi-machine race over impaired Wi-Fi. Existing
loopback/state-machine tests provide useful network coverage but do not establish
all gameplay timing or cross-platform determinism properties. Short smoke runs
cannot establish long-session stability or race-completion correctness.

I would address #26–#28 first, then the directly reproducible gameplay/audio/score
defects and #33, followed by the latent #34. The current regressions are valuable,
but their passing results coexist with gaps in simulation-vs-render timing,
multi-listener behavior, and older loader validation. Each defect's regression
coverage belongs with its fix, as already recorded in the task list.

Two broader proposals are **awaiting approval and have not been added to
task.md**: a reusable end-to-end network replay/state-comparison harness across
architectures and render cadences, and a release-device acceptance matrix for
controllers, audio, mobile suspend/resume, and long sessions. Both would improve
confidence beyond the focused defect tests, but neither is treated here as an
already-authorized feature or engineering project.
